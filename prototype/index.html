How your mail is handledAttachments, previews and how long things are kept.
          

            

              
NeverRaw attachment disk storage

              
25 MBMaximum source file

              
5 minRAM preview lease

              
64 MBGlobal preview RAM cap

            

            
Attachments are fetched from the source mailbox into an isolated worker that keeps them in memory only, then the raw bytes are destroyed. A safe preview is made in memory when someone clicks an attachment.

            
PDF pages are shown as safe pictures made in the isolated worker; images are decoded and re-encoded; plain text is escaped. Office files show their text. HTML, SVG, programs and archives are never shown directly.

            
Attachment filenames, type, size and the AI summary are encrypted with the review item and are removed when the item is Reviewed, Archived, Binned or expires (see Reviewed & archived). The original attachment stays only in the person's own mail account.

            
Email text is always treated as untrusted: it cannot give the AI tools or new permissions. Only structured results are kept, not raw model responses. Administrators manage the system, not other people's private mail.

          

        

        
Lock or unlock EnveliqNormally nothing to do here. Use this to lock everyone out, or to unlock after a restart.
          

          
The passphrase is sent only to the local secure backend over the same trusted application boundary, is never written to storage and is not retained by this page after the request.

          

            

          

          

            
            
            
          

          
For the first release, a backend restart requires an administrator to unlock the vault. A future TPM/HSM or external vault option can provide unattended secure unlock.


          

        

        
What Enveliq promises never to doThe rules it keeps about your mail and your secrets.
          

          
No raw email body persistenceOnly structured retained results are allowed into persistent storage.

          
No raw attachment persistenceOriginal attachment bytes are processed and previewed only in RAM. Safe preview derivatives expire automatically and are never written to application storage.

          
No provider secrets returned to browserPasswords, refresh tokens and API keys are write-only from the UI.

          
Mailbox owner separate from administrator roleAdmin rights do not automatically grant access to another user's private mailbox.

          
Email content treated as hostile inputThe LLM receives no HA tools, shell, filesystem, arbitrary network or secret access.

          
Secrets and message content excluded from logsRequest bodies are not logged and application logging includes redaction.
